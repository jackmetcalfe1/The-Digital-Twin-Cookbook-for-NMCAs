# Recipe 10 — Review, iterate and monitor outcomes

> **Decision question:** Did the role create value, and what should change next time?

## Goal

Make the cookbook a learning system rather than a one-off assessment. This recipe
captures whether the chosen role created value and what should change in the next
iteration.

## When to use this recipe

- After a pilot or implementation has run for long enough to generate evidence.
- As the closing step of a full pathway, or as a standalone post-pilot review.
- When deciding whether to scale, adapt, pause or discontinue a role.

## Framework modules operationalised

- Iteration
- Evidence quality
- Learning

## Ingredients / required inputs

- Implementation evidence and value indicators (from Recipe 6)
- Stakeholder feedback and operational metrics
- Cost data and risk logs
- Updated policy or strategy context

## Method / step-by-step process

1. Review outcomes against the value indicators defined in Recipe 6.
2. Compare expected and actual costs, capabilities, risks and benefits.
3. Record implementation lessons and stakeholder feedback.
4. Update assumptions, templates and scoring rules.
5. Identify whether the role should be scaled, adapted, paused or discontinued.
6. Feed lessons back into the framework and future cookbook versions.

## Templates / tools used

- Learning log and outcome review
- Value pathway canvas
- Gap register
- Risk, assumption and uncertainty register

## Outputs / plating up

- Outcome review
- Learning log
- Updated value pathway
- Revised gap register
- Recommendations for next cycle and cookbook improvement

Feed the learning log back into the framework and the next iteration of the cookbook.

## Quality checks and evidence notes

- Outcomes are measured against the Recipe 6 indicators, not new ad-hoc ones.
- Expected-versus-actual comparison is documented for cost, capability and benefit.
- A scale / adapt / pause / discontinue recommendation is made explicitly.

- Revisit any recipe whose assumptions the review has invalidated.
