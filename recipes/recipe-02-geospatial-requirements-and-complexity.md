# Recipe 2 — Assess geospatial requirements and DT complexity

> **Decision question:** What geospatial data, functionality and interoperability does the use case require?

## Goal

Make the geospatial contribution explicit. This recipe prevents geospatial
requirements from being hidden under generic technology language and helps the
NMCA understand the complexity of the proposed Digital Twin case.

## When to use this recipe

- Immediately after a use case has been defined (Recipe 1).
- When estimating the data, standards and interoperability burden of a case.
- When you need an evidence base for later role and capability decisions.

## Framework modules operationalised

- DT use-case requirements
- Standards and interoperability

## Ingredients / required inputs

- Use-case brief (from Recipe 1)
- Existing geospatial datasets and metadata catalogues
- Technical architecture, SDI components and APIs
- Standards requirements and 2D / 3D / 4D data needs
- Relevant complexity dimensions from Metcalfe et al. (2024)

## Method / step-by-step process

1. Describe the spatial, temporal and representational requirements of the use case.
2. Score the case using a DT-Geospatial Complexity Index or equivalent requirements matrix.
3. Assess spatial extent, geometric complexity, temporal resolution, data
   diversity, data acquisition, analytics, CRS complexity, data sharing,
   visualisation, storage and processing requirements.
4. Identify required standards, metadata, APIs and interoperability arrangements.
5. Classify the use case as low, medium or high geospatial complexity.
6. Record **minimum viable** geospatial requirements, not idealised maximum requirements.

## Templates / tools used

- Geospatial requirements profile
- DT-Geospatial Complexity Index scoring sheet

## Outputs / plating up

- Geospatial requirements profile
- DT-Geospatial Complexity score
- Interoperability checklist
- Minimum viable geospatial requirements statement
- Implications for NMCA role and capability

Carry the requirements profile and complexity score into the readiness and role recipes.

## Quality checks and evidence notes

- Requirements are stated as minimum viable, not aspirational maximum.
- Each complexity dimension is scored against evidence, not impression.
- Standards and interoperability needs are explicit and traceable.
